## 按渲染后的相邻字符检查

本指南在中文与直接相邻的拉丁字母或阿拉伯数字之间留一个半角空格。链接和强调只是包裹文本的语法，空格根据读者实际看到的字符决定。中文标点两侧紧排，同一个中文短语内部保持连续。

| 场景               | 源文件写法                                                    |
| ------------------ | ------------------------------------------------------------- |
| 英文名夹在中文里   | `使用 GitHub 审阅文档。`                                      |
| 中文与数字         | `构建生成 12 个条目。`                                        |
| 英文词紧邻中文逗号 | `支持 YAML，配置示例见下节。`                                 |
| 中文和行内代码     | 在“修改”和反引号包裹的 `index.config.json` 之间留一个半角空格 |
| 中文链接和后续正文 | `按[中文排版](/docs/typography/overview)检查正文。`           |

当链接从英文字母开始时，可写成 `使用 [Markdown](/docs/elements/markdown) 编写正文。`。在源码中检验链接内部第一字和最后一字，再检查完整渲染的结果。

## 保留需要逐字复制的内容

命令、URL、文件名、代码字符串、日志片段和产品正式拼写使用原始字符。排版时把可读正文与可复制内容明确区分开。把 `--output=search-index.json` 放进行内代码，连接号、点号和等号都按命令语法输入。

发布前从预览页复制一段命令，检查半角引号、空格和行首缩进。界面文字包含固有格式时，可在引号中保留显示形式，并在正文解释。

## 使用自然的分段和换行

段落用空行分开。行宽随设备变化，可交给浏览器处理。在代码块中保留语法所需的缩进。对中文与西文间距的背景，可以对照[中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)中的录入习惯，以及 W3C 对[横排混排](https://www.w3.org/TR/clreq/#mixed_text_composition_in_horizontal_writing_mode)的说明。
