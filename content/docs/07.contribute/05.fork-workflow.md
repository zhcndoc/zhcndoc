## 确认基准仓库和分支

先打开目标仓库的贡献说明，核对接收文档修订的分支。中文项目可能按版本维护多条分支，站内规范源文件则位于简中文档站点仓库。记录目标页面的版本和基准提交，再从对应分支开始。只有一处小改动时，也可以按[网页编辑与本地预览](/docs/contribute/editing)选择 GitHub 网页编辑。

在 GitHub 派生目标仓库，从自己的副本克隆到本地。用下面的只读命令查看当前环境中的仓库关系和工作区状态。

```bash
git remote -v
git branch --show-current
git status --short
```

`origin` 通常指你克隆的副本。远程名称由本地设置决定，`upstream` 也可能是中文仓库中的一个分支。可以按[比较上游更新](/docs/translation/upstream-sync)区分这两种用法。

## 把一个任务放在一个分支

为任务创建有意义的分支名，例如 `docs/describe-search-output`。编辑前记下题目和涉及的文件。提取共用说明时，可以把移动和正文改写分成便于审阅的提交。预览后查看差异，检查格式化是否顺带修改了无关页面。

保留原文引用、警告文字和二进制资源的版本信息。多页重译时，按目录或读者任务给出顺序，确保任何一个中间提交都能说明为什么改这些文件。

## 处理基准变化

进入审阅前比较目标分支和工作分支。若同一段正文在上游也有修改，先以新的页面内容和行为为依据重新审视你的改动。解决冲突后渲染页面，检查相邻的标点、链接、嵌套列表和代码块，再更新[拉取请求中的验证记录](/docs/contribute/pull-requests)。
