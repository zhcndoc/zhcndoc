## 让审阅者知道从哪里读

拉取请求有多轮修订时，在描述中写明最新需要复查的页面和验证路径。请求技术审阅时指定需要确认的行为，例如“将 `maxEntries` 设为 `0` 会生成空索引”。请求语言审阅时提供同版本原文、项目术语和读者上下文。

收到反馈后先判断它影响准确性、操作结果还是表达。修订后，在原讨论中说明改动所在的页和已重跑的步骤。遇到术语分歧时，引用实际界面、当前术语表或上游定义，再说明不同译法会不会影响读者检索。

## 复查合并条件

维护者可在合并前核对审阅状态、项目检查和最新差异。变动涉及生成内容、配置默认值或页面地址时，复查对应生成结果、版本适用性和跳转。若基准分支在审阅期间更新，重新检查双方交叠的段落及依赖。

| 审阅意见                 | 可以复查的回应                               |
| ------------------------ | -------------------------------------------- |
| 示例缺少运行目录         | 在命令前注明仓库根目录，并从新克隆的目录重跑 |
| “索引”在两页使用不同译名 | 按术语表统一相关标题和正文，并确认搜索可找到 |
| 页面移动后旧入口失效     | 补上地址对应关系并实际打开旧链接             |

## 检查发布结果

合并后按项目发布方式确认页面何时可见。文档上线时，从导航、站内链接和搜索各打开一个受影响入口。仍需跟进的旧版本或翻译任务保留在相关议题中，并注明已经验证过的版本。

首次进行审阅时，可按[拉取请求审阅流程](/docs/reviewing/pull-request-review)逐项记录证据。
