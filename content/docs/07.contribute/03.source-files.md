## 从页面找到源文件

优先使用页面的编辑入口。入口不可用时，在目标分支搜索页面标题、独特的一句话或前端路由中的文件名。仓库中可能同时存在英文页、译文、版本副本和构建产物，打开文件后核对语言、版本和导航位置。

以本指南为例，`content/docs/04.elements/01.markdown.md` 对应 `/docs/elements/markdown`。数字前缀用于同级排序。`.navigation.yml` 中的标题和 Lucide 图标用于章节导航。页面的 `title` 用作正文标题，`description` 用于摘要和搜索。

## 找到内容实际维护的位置

| 页面上看到的内容               | 优先查找的位置                       |
| ------------------------------ | ------------------------------------ |
| 一段只在当前页面出现的说明     | 本页的 Markdown 源文件               |
| 多页共享的安装要求或说明       | 被复用的 Markdown 片段或组件参数     |
| 根据定义生成的字段表或类型签名 | 类型定义、源代码注释或生成脚本的输入 |
| 发布页的版本记录               | 对应版本的发布记录或变更集源文件     |

发现内容由生成流程维护时，改写生成输入并执行项目声明的生成命令。再检查所有受影响的页面。参考[配置项参考](/docs/examples/configuration-reference)里的字段核对方法，可以发现文档与实际默认值的差异。

## 移动页面时检查入口

搜索旧路径、旧标题锚点和导航项。迁移同一主题时记录旧地址与新地址的对应关系。相似功能有多条版本路径时，逐一确认链接指向的版本，按[链接与锚点](/docs/elements/links)验证导航、正文和外部入口。
