## 选一处能验证的改动

适合起步的任务包括修复失效链接、补上遗漏的前置条件、纠正术语或验证一段命令。先打开当前页面，再从[项目目录](/project)找到对应的中文仓库和上游来源。

遇到需要重写多页、调整导航或统一术语的任务时，先在对应仓库的 Issue 里说清读者遇到的问题、受影响的页面和改动范围。风格指南的修改建议可以提交到[简中文档的 Issue 列表](https://github.com/zhcndoc/zhcndoc/issues)。

## 写出可复查的问题

提供当前页面、具体标题或原句，说明影响的版本和你观察到的结果。报告翻译差异时，把上游同一版本的链接放进问题描述。涉及命令失败时，给出最小步骤和必要的错误输出，并用占位符替换私有路径和凭据。

任务范围明确后，按[编辑与预览](/docs/contribute/editing)检查改动效果。

## 找到合适的贡献方式

| 你发现的问题                 | 可以怎样参与                                                                |
| ---------------------------- | --------------------------------------------------------------------------- |
| 一处错字、术语误用或链接失效 | 修改具体语句并核对目标                                                      |
| 步骤在某环境无法执行         | 提供[可复查的问题报告](/docs/contribute/issues)，或在复现后补充条件         |
| 多页重复或含有过期说明       | 说明读者任务，按一个子任务[建立工作分支](/docs/contribute/fork-workflow)    |
| 暂时无法直接编辑             | 提供复现结果、同版本原文链接或[审阅意见](/docs/reviewing/feedback-examples) |

如果多个页面共享同一个问题，先挑一条常用入口跑通。把实际原因和验证方法写清后，再检查其他页面是否受影响。
