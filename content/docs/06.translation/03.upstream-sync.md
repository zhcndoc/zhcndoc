## 记录两个可核对的基准

从[项目目录](/project)找到中文仓库和上游地址。确认项目约定的原文分支、文档路径和译文分支，记录上次纳入译文的上游提交以及这次要处理的目标。站点的上游同步工作流把原文或筛选后的文件同步到中文仓库的 `upstream` 分支。具体路径以各项目配置为准。

区分远程仓库名和分支名。`origin/upstream` 是本地记录的远程跟踪分支。命令中的 `origin` 取决于你克隆仓库时的设置。记录确切的提交可以避免比较过程中分支更新导致的变化。

## 按文件状态处理差异

将 `old_source` 和 `new_source` 设置为实际的上游提交号，再从中文仓库根目录查看差异。示例假定原文在 `docs/`，实际目录按项目调整。

```bash
git diff --name-status --find-renames "$old_source" "$new_source" -- docs/
git diff "$old_source" "$new_source" -- docs/search.md
```

| 上游变化     | 中文页要检查的内容                   |
| ------------ | ------------------------------------ |
| 新增页面     | 路径、元数据、导航和引用             |
| 修改正文     | 条件、默认值、输出、示例和相关术语   |
| 移动或重命名 | 中文导航、旧路径、标题锚点和共享片段 |
| 删除或合并   | 替代页面、版本适用范围和旧入口       |

对照同段上下文理解实际变化。对中文页面已有的读者补充，验证其与新版本的兼容性，并在提交中记录调整理由。筛选同步的项目还需要核对差异只覆盖已纳入的路径。

## 交付可以复查的更新

在 PR 中记录两个上游端点、涉及的页面、验证结果和剩余工作。需要保留多版本时，在相关页注明中文说明对应的版本。按[译文审阅](/docs/translation/review)对照原文差异、代码和页面渲染。
