## 明确条件覆盖的范围

先把原句拆成条件、动作和结果，再按中文的自然语序重组。条件修饰哪一步要写清楚。例如，“仅在离线模式下索引才可复用”要求读者先判断模式。把“仅”移动到别处，可能改变适用范围。

| 示例原文                                        | 推荐译法                       | 复查点                       |
| ----------------------------------------------- | ------------------------------ | ---------------------------- |
| Rebuild only if the output path changes.        | 仅当输出路径改变时才重新构建。 | 条件修饰重新构建             |
| Omit the option to use the default path.        | 省略此选项时使用默认路径。     | 描述缺省行为                 |
| You may see a warning on first start.           | 首次启动时可能出现警告。       | 表达出现的可能性             |
| At most ten records are returned.               | 最多返回 10 条记录。           | 上限可以取到                 |
| Pass an empty array to exclude all directories. | 传入空数组会排除所有目录。     | 空值和省略的语义需要分别核对 |

## 让代码和界面仍可对应

原文提到 `maxEntries` 或 `INDEX_FILE_MISSING` 时，保留标识符并通过正文解释含义。代码中的示例输入可能是解析器的固定值。翻译前辨别字符串是给读者看的提示、对外协议值，还是要匹配的实际输入。可翻译注释和说明文字，复制执行验证其余部分。

界面只有英文时，可以写“选择 ‘Rebuild Index’（重新生成索引）”并保留按钮实际文字。界面已有中文时，对照该版本确认译名与位置。

## 核对易错的比较和否定

用一个与限制相邻的值复查语义。例如，条件是“至少 10 条”时，用 9、10 和 11 分别验证。原文中 `unless`、`until` 和 `only` 容易影响读者选择，必要时把条件拆成完整句子。术语选择遵循[术语与命名](/docs/style/terminology)，原文版本和差异处理见[上游同步流程](/docs/translation/upstream-sync)。
