## 用完整的条件和动作组织句子

把容易漏看的限制放在动作前，例如“启用了离线搜索时，构建输出需要包含索引文件”。动作有明确主体时写出主体，例如“浏览器从静态目录加载索引”。需要判断先后时，用“保存后”“重新加载时”标明顺序。

遇到多层条件时，把可以独立判断的条件写成多条。复查“与”和“或”的关系。例如，“启用了标题索引且输出目录可写”要求两项同时满足。“改用系统生成的路径或手动指定路径”描述同一个任务的两种入口。

| 容易误读的表述                   | 改写                                     |
| -------------------------------- | ---------------------------------------- |
| 启用工具后它会加载它。           | 启用搜索后，浏览器加载索引文件。         |
| 配置要么可选，除非要自定义。     | 使用默认输出路径时可以省略此配置。       |
| 保存并在文件存在时重试构建。     | 保存配置。确认输出目录存在后，再次构建。 |
| 超过 100 条时截断到 100 条以内。 | 超过 100 条时保留排序后的前 100 条。     |

## 把长句拆成可逐条核对的事实

一句话同时解释默认值、触发条件和异常时，可拆成三句。例如，“默认写入 `search-index.json`。设置了 `search.output` 时使用指定路径。目标目录不可写时构建失败。”这样也便于译者逐项对照原文。

校对时检查否定的作用范围。“未生成索引时禁用搜索”陈述缺失条件触发的行为。“禁用索引生成”则是设置项的动作。遇到“仅”“首次”“至少”“最多”这类词时，标出它们修饰的对象。

## 校对正文和代码中的拼写

用站内搜索对照术语表和邻近页面。把代码标识符、引号里的界面字样、版本号和路径逐一对照真实来源。中文拼写检查可能把产品名或技术词标成疑似错误，可以按[文档质量检查](/docs/reviewing/quality-tools)逐项确认。
