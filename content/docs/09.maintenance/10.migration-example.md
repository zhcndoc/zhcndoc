## 确认起始状态

本示例使用一个虚构的索引工具。从 1.x 升到 2.x 时，输出路径由 `indexFile` 改为 `search.output`。显式配置了输出路径的项目需要更新配置。依赖默认输出名的项目需要核对部署流程，因为默认文件名也由 `index.json` 变为 `search-index.json`。

开始前记录当前构建所用的配置文件、索引的实际位置、哪些部署脚本读取它，以及一次已成功执行的查询。这些信息既用于迁移，也用于判断是否能回退。

## 迁移配置

1.x 的示例配置如下。

```json
{
  "indexFile": "public/docs-index.json"
}
```

在 2.x 中，把同一路径移到 `search.output`。保留你的实际路径。

```json
{
  "search": {
    "output": "public/docs-index.json"
  }
}
```

如果此前依赖默认路径，可以显式配置旧路径，也可以选择新默认路径并更新读取端。先选择目标路径，再更新构建和部署配置。

## 验证并记录结果

1. 依项目的构建命令重新生成索引，核对输出文件路径和条目数。
2. 检查部署产物确实包含生成的文件。
3. 打开预览站，用先前记录的查询验证读到同一个文档。

出现“发布目录没有索引文件”时，从[故障排查](/docs/maintenance/errors)所示的产物和路径检查入手。只有旧运行时与已部署数据兼容时，才恢复旧依赖和配置并重新构建。维护真实指南时，把虚构的字段、版本和验证步骤替换为项目中已经核实的信息。
